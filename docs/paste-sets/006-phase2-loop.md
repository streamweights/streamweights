Every existing command writes a manifest from now on. This is what makes an eval table reproducible.
Logits output. Add to the engine an optional per-token top-k log-probability output (--logprobs K, K up to 64; --full-logits writes a .npy per row for sets under 200 rows, refuse above with the size it would be). Output rows carry logprobs: [{token_id, logprob, top: [[id, logprob], ...]}]. Memory check: batch x vocab x 2 bytes per step stays inside the budget. [GPU] verify on 0.5b that the top-1 matches the generated token and that log-probs sum to within 1e-3 of 1 after exp.
spill distill. Two modes. Generation: spill distill <teacher> prompts.jsonl --logprobs 32 runs the existing job engine with logits on and writes a distillation JSONL (prompt, teacher completion, per-token top-k). Teacher-forced: spill distill <teacher> targets.jsonl --score where each row has messages plus an assistant target; the teacher scores every target position with no sampling, prefill-only, and writes per-position top-k plus the target token's log-prob. Both reuse batching, checkpointing, resume, and the live tail. Pre-run line states mode, tokens to score, and estimated time from calibration (prefill-bound, so from measured prefill rate, not pass time). [GPU] verify both modes on 0.5b against an mlx-lm reference computed independently.
Adapters at inference. spill run <base>+<adapter> evals.jsonl where <adapter> is a local directory or Hugging Face repo in PEFT safetensors or mlx-lm layout. Both engines apply LoRA deltas at the layer boundary; for the streamed engine, adapter weights stay resident (they are small) and are applied after each layer's base weights are bound. spill adapters lists local adapters. [GPU] identity test: 0.5b with a known mlx-lm-trained adapter, streamed versus resident, identical greedy output on 20 prompts.
Metrics. streamweights/metrics/: exact_match, contains, regex, json_field, judge (a second model run through the same engine with a rubric prompt, scored 0 to 1), and script (a user Python file exposing score(row) -> float). Each metric takes the result row and the eval row's expected field. Pure functions, fully CPU-tested.
spill eval. spill eval evals.jsonl <model-a> <model-b> ... [--metric exact_match] [--judge <model>]: runs each model that has no cached run for this exact input hash, then prints one table (model, quant, adapter, rows, metric mean, p50 and p95 per-row latency, tokens) and writes runs/eval-<id>/table.md and a diff.jsonl of rows where models disagree. Cached runs are reused by hash; --rerun forces. spill eval on a single model is the existing run plus scoring. [GPU] verify with 0.5b versus 0.5b+adapter on sample.
